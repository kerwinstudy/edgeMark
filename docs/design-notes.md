# 实现说明

记录这个项目的关键设计取舍。面向想改代码的人，普通使用不需要看。

## 目录结构

```
edgeMark/
├── start.command            双击启动（macOS）
├── server/index.js          本地服务：静态资源 + 受限文件 API + 搜索 + 改动监听 + AI 转发
│                            （只用 Node 内置模块，零后端依赖）
└── public/
    ├── index.html
    ├── app.js               目录树、文件管理、标签栏、双向同步、搜索、主题、AI 助手
    ├── styles.css           浅色 / 深色两套主题变量
    └── vendor/              离线资源，无构建步骤
        ├── vditor/          左侧所见即所得编辑器（Vditor 4.0.0，MIT）
        ├── codemirror/      右侧源码面板（CodeMirror 5 + gfm/markdown/xml + overlay 等插件）
        ├── github-markdown-{light,dark}.css
        ├── markdown-it.min.js
        └── prism/           代码高亮（渲染 AI 回答用）
```

CodeMirror、github-markdown-css、Prism 取自本机 MarkText 的 `app.asar`。

## 编辑器选型

**为什么不用 Muya。** MarkText 的编辑器内核 Muya 就在本机 MarkText 的 `app.asar` 里，
它才是「MarkText 本体」。但 Muya 的源码是为 Vite 写的（含 `katex/dist/katex.css?inline`
这类 `?inline` 导入），要跑起来必须先引入 esbuild 打包并写插件处理，还要拉进 mermaid /
katex / vega / flowchart 等 22 个重依赖。Vditor 的 `dist/index.min.js` 是自包含 UMD，
一个 `script` 标签即可，`ir` 模式的行为与 Typora 一致，所以选了它。

**完全离线。** Vditor 默认从 unpkg 拉 Lute 引擎、图标、highlight.js、KaTeX、以及
mermaid / plantuml / echarts 等图表渲染库。这里把 `cdn` 指向 `/vendor/vditor`，
并按它的目录约定把资源**全部**拷到本地（约 22MB）。

> 这些图表库是**按需加载**的——文档里出现 ```` ```plantuml ```` 之类的代码块时才会去取。
> 而它的加载器是 `<script>` + `onerror → reject`，且调用处没有 `.catch()`，
> 所以**少任何一个文件都会变成一条未处理的 Promise 拒绝**（页面上显示红条）。
> 早期版本裁掉了这些库，踩过这个坑，现已全部补齐。

## 双向同步

**内容真源只有一个。** 每个标签持有一个 `CodeMirror.Doc`（右侧源码面板），它是该文件
内容的唯一真源，Vditor 只是它的一个视图。这样保存时直接取 doc 即可，不用纠结两边谁新。

**死循环防护。** 两侧任一变化都推给另一侧，用 `state.syncing` 标志阻断回环。

Vditor → 源码是立即同步（保证 doc 永远最新）；源码 → Vditor 防抖 600ms（每次都要让
Vditor 重新解析并重建 DOM，代价高）。切换标签时会清掉排队的同步，避免落到错误的标签上。

## 大文件性能

三个措施，缺一不可：

1. **源码面板不设 `viewportMargin: Infinity`。** 设了会让 CodeMirror 把整个文档渲染成
   DOM 而不是只渲染可视区域，大文件下直接卡死。这是最容易踩的坑。
2. **Vditor → 源码用最小差异替换，不用 `setValue`。** 全量 `setValue` 会重建整个文档的
   DOM，每敲一个字都卡。改成算出公共前后缀、只 `replaceRange` 变化的那一段：
   500KB 文档下单次按键约 1.3ms，实际只替换 1 个字符。
3. **超大文件关闭所见即所得渲染。** Vditor 没有虚拟滚动，是整篇文档一次性建成 DOM；
   CodeMirror 有视口渲染，大文件反而没问题。所以超过 `WYSIWYG_MAX_CHARS`
   （当前 300000 字符）就退回「只用源码面板编辑」，左侧显示提示。

## `Cmd+1`~`Cmd+6` 怎么接的

Vditor 把等价的标题功能硬编码在 `⌥⌘1`~`⌥⌘6` 上，内部走 `It(vditor, "## ")`，
和工具栏的标题按钮同一条路径。与其去调它的内部函数（不是公开 API），不如拦下 `Cmd+N`
再派发一个 `altKey=true` 的同键事件，让它自己的成熟逻辑处理。派发出去的事件带 `altKey`，
不会再命中这个分支，不会递归。

### 跨平台差异

Vditor 的快捷键字符串里那个 `⌘` 表示「**平台的主修饰键**」，不是字面的 Cmd。
它的匹配器是：

```js
!(isMac(t) || t.altKey || t.shiftKey || t.code !== e)
```

而 `isMac` 在非 Mac 平台上的判定是 `!metaKey && ctrlKey`（也就是 Ctrl）。所以：

- **Vditor 自带的**（加粗 / 斜体 / 链接 / 撤销…）在 Mac 上是 `Cmd+X`，
  在 Windows 上自动变成 `Ctrl+X`，不用管。
- **标题**：Mac 上是 `⌥⌘1~6`，**Windows 上原生就是 `Ctrl+Alt+1~6`**。

因此 `⌘1~6` 的桥接**只在 macOS 上启用**（`IS_MAC` 判断）。Windows 上 `Ctrl+1`~`Ctrl+9`
是浏览器切换标签页的快捷键、页面拦不住，如果也去拦会变成「既切了标签页又插了标题」。
非 Mac 上不拦，交给 Vditor 自己的 `Ctrl+Alt+N`。

保存（`Cmd/Ctrl+S`）和代码块（`Cmd/Ctrl+Shift+K`）的处理器同时接受 `metaKey` 和
`ctrlKey`，两个平台通用。

## 接口

所有路径参数都是**相对根目录**的路径，服务端会拒绝任何越出根目录的请求。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/config` | 当前根目录、最近使用、常用目录 |
| POST | `/api/config/root` | 切换根目录，`{ root: "/abs/path" }` |
| GET | `/api/tree?dir=<rel>` | 列出某目录的直接子项（目录 + 可编辑文本文件） |
| GET | `/api/file?path=<rel>` | 读取文件内容 |
| PUT | `/api/file` | 保存，`{ path, content }` |
| POST | `/api/file` | 新建文件，`{ path, content? }` |
| POST | `/api/dir` | 新建文件夹，`{ path }` |
| POST | `/api/rename` | 重命名 / 移动，`{ path, to }` |
| DELETE | `/api/entry` | 删除，`{ path }` —— **移入废纸篓，不做永久删除** |
| POST | `/api/reveal` | 在访达中定位，`{ path }`（仅 macOS） |
| GET | `/api/search?q=&regex=&case=&limit=` | 全文搜索 |
| GET | `/api/image-dir?dir=<rel>` | 读该目录生效的图片保存目录 |
| POST | `/api/image-dir` | 设置，`{ scope: 'global'\|'dir', dir?, name }` |
| POST | `/api/upload` | 接收图片（multipart），存到文档旁的图片目录 |
| GET | `/api/watch` | 订阅「已打开文件被外部改动」（SSE 长连接） |
| POST | `/api/watch` | 设置监视清单，`{ paths: [...] }` |
| GET | `/api/routes` | 列出服务端实际注册的接口（前端启动自检用） |
| GET | `/api/ai/config` | AI 配置。**只回 `hasApiKey` 布尔值，不回密钥本身** |
| POST | `/api/ai/config` | 写 AI 配置，`{ baseUrl, model, apiKey? }` |
| POST | `/api/ai/chat` | 转发一次对话，SSE 流式返回 |

### 服务端自检

页面启动时会拿 `/api/routes` 和自己的接口清单对一遍。这个项目是「改完代码要重启本地
服务」的形态，很容易出现「页面刷新到新版、后台还是旧进程」，旧进程的表现是「未知接口」
这类没法排查的报错。对不上时页面会直接提示「服务端是旧版本，请重启」。

### 全文搜索

用**纯 Node 实现**，不是 ripgrep。MarkText 用的 `@vscode/ripgrep-darwin-arm64` 是平台
专属二进制，放进公开仓库只有 Apple Silicon Mac 能用。markdown 笔记这个量级纯 Node 完全够。

带保护上限：最多扫 4000 个文件、单文件 2MB、返回 200 条（可调）。默认按字面量搜索，
`regex=1` 走正则（非法正则会返回明确报错）。

### 本地图片

**插入**走 Vditor 的 `upload.url`。这一步必须显式配置，因为它的内部分支是
`if (upload.url || upload.handler) { 走上传 } else { readAsDataURL(...) }` ——
不配的话它会用 `FileReader` 把图片读成 **base64 data URL 直接写进 markdown**。

走 `upload.url` 而不是 `upload.handler`，是因为**插入动作交给 Vditor 自己做更可靠**：
它清楚自己的选区和模型；而 `handler` 的契约是「返回字符串=错误提示」，插入得自己调
`insertValue`，可文件对话框会夺走焦点、选区未必还在。

**显示**靠的是**让页面 URL 跟着当前文件走**：打开 `sub/notes.md` 时地址变成
`/sub/notes.md`，于是 `assets/a.png` 被浏览器解析成 `/sub/assets/a.png`，
服务端再从根目录把这张图发出来。

> **为什么不用「改写 DOM 里 img 的 src」这个显而易见的做法**：Vditor 的 `getValue()` 是
> `lute.VditorIRDOM2Md(ir.element.innerHTML)` —— **从 DOM 反推 markdown**。改 `src`
> 会被写回文档、污染用户的文件。所以必须绕开 DOM。

**图片保存目录**支持两级：全局默认 + 按目录覆盖（对子目录生效，更具体的优先）。
设置存在服务端配置里，因为它决定的是文件写到哪，属于文件系统的事；存服务端也让所有
浏览器看到的设置一致。

`assets` 是 Typora / Obsidian / 很多静态站生成器的主流约定，好处是可预期。但如果某个
目录里本来就有同名的 `assets`（比如放构建产物的），插入图片会混进去——这时给那个目录
单独设一个别的名字即可。

服务端对页面 URL 形式的请求：先找 `public/` 下的静态资源，再按根目录找图片，都不是的话，
如果扩展名是已知静态资源类型就 404（避免打错路径拿到一个 HTML），否则回退 `index.html`
（单页应用，页面 URL 带路径也能正常打开）。

### 文件管理

新建的位置跟随**最后点选的目录**（或最后打开文件所在的目录），对话框里会写明具体位置。

**删除一律移入 macOS 废纸篓，绝不永久删除。** 只做同卷 `rename`；如果根目录在外接硬盘等
其他卷上会失败，这时**明确报错而不是退化成硬删**。废纸篓里已有同名文件时会加时间戳后缀，
不覆盖。

不允许创建以 `.` 开头的名称——目录树本来就不显示隐藏文件，建了会「消失」，所以直接拒绝。

拖拽时前端会拦掉「把目录拖进自己或自己的子孙里」，服务端也会按路径规则拒绝。

### 自动保存与外部改动

- **自动保存**：默认关闭，在「···」菜单里开。开启后编辑停止 1.2 秒落盘。
- **外部改动监听**：服务端用 `fs.watch` 监听**文件所在的目录**而不是文件本身——
  多数编辑器保存是「写临时文件 + 原子重命名」，直接监听文件会在第一次保存后就丢掉 watch。
  标签干净时自动重载；**有未保存改动时只提示冲突，不静默覆盖**。

## AI

### 请求为什么必须经本地服务转发

浏览器不直连上游。原因是绝大多数 LLM API 不允许跨域，而且密钥不该出现在页面里。
上游返回的 SSE 会在服务端被收敛成 `{"delta":"..."}` / `{"error":"..."}` / `[DONE]`
三种事件，前端不用关心各家格式差异。

文档用 `===== 文件内容开始 =====` 这种显式分隔符包裹，而不是代码围栏——文档里本来就
可能含 ` ``` `，用围栏会被提前截断。

### 让 AI 直接改文件

AI 输出结构化的修改块，前端解析成 diff 预览，**用户点「应用到当前文件」才生效**：

```
<<<<<<< SEARCH
（要被替换的原文，必须与文档逐字符一致）
=======
（替换后的内容，留空表示删除）
>>>>>>> REPLACE
```

**为什么不用 function calling**：各家「兼容 OpenAI」的端点对工具调用的支持参差不齐，
用结构化文本块对任何模型都通用，而且天然可以在界面上做人工确认。

**应用时的安全约束**：

- **精确匹配 + 必须唯一。** 找不到、或出现多次，都拒绝应用并说明原因——不做模糊猜测，
  避免改错地方。
- **唯一的容错是行尾空白。** 模型最常见的偏差是行尾多/少空格，这时退化成「逐行忽略行尾
  空白」匹配，并在结果里标明不是精确匹配。
- **逐处独立。** 某处失败不影响其他处，会列出哪些跳过、哪些应用。
- **只改内存，不落盘。** 应用后只是标记为「未保存」，仍由用户按 `⌘S` 决定。
- 应用前会**基于当前文档内容重新校验**一遍，所以 AI 回复之后用户又手动改过文件也没关系。

### 引用跳转

回答里的行内代码如果能在当前文档里原样找到，就做成可点击的跳转。

刻意不用「让模型输出行号」的方案——大模型数行号并不可靠。直接拿原文片段回文档里搜，
既准确又不需要改提示词。

## 已知取舍

这两条是引擎层面的限制，不是没做，是做不了：

- **左侧撤销历史不跨标签保留。** Vditor 没有「切换文档」的 API，`setValue()` 就是替换
  内容，撤销栈在实例内部，外部碰不到。唯一的办法是每个标签一个 Vditor 实例，但每个实例
  都要跑一遍 Lute 解析 + 建 DOM，标签一多就是叠加的开销，不划算。
  **右侧源码面板的撤销历史是按标签各自的 `CodeMirror.Doc` 保留的**，`⌘Z` 在那里一直有效。
- **AI 应用修改后，左侧 Vditor 的撤销栈覆盖不到这次改动。** 同样因为 Vditor 没有公开的
  撤销栈 API。缓解办法：应用后焦点会自动移到右侧源码面板，`⌘Z` 在那里立刻可用。

其它：

- 图片只服务图片类型（不做成通用文件读取接口），且仅限根目录内。
- 全文搜索有上限（4000 文件 / 2MB / 200 条），超大仓库会截断并提示。
- 导出 PDF 依赖浏览器的打印对话框（Edge 里选「另存为 PDF」），不引入 PDF 生成库。
- 深色主题与自动保存存在 localStorage，不在 `~/.edgemark/config.json` 里——它们是纯
  界面偏好。图片保存目录存在服务端配置里，因为它决定文件写到哪。
- 左侧打字时右侧会重设内容，所以右侧的光标位置不保留（滚动位置会保留）。

## 配置迁移

旧版本把配置放在项目的 `.edgemark-config.json`。首次启动会**自动迁移**到
`~/.edgemark/config.json`：先写新文件、再读回来核对一致、确认后才删除旧文件。
校验不过就保留旧文件并告警，不会丢配置。
